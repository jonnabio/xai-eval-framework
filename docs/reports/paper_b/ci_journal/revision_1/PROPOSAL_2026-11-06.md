### Reviewer 1: major comments

**R1-M1 (novelty against the published comparison).** We agree that the previous version
relied too much on the earlier study. The revision answers this in three ways. First, every
result now comes from a new cohort designed and run for this study, on one host, with four
explainers and seven datasets; no number is taken from the earlier work. Second, the analysis
asks a different question: not whether SHAP is better on average, but when the ordering of the
methods depends on the model, the configuration and the measurement protocol. That calls for
configuration sensitivity (§4.3) and validity controls (§4.4) that the earlier study did not
have. Third, cost is reported in hardware-independent terms (model calls, complexity) next to

[R: one sentence on the finding that is new.]

**R1-M2 (independence of the configurations).** We thank the reviewer for this important
comment. On re-examining the design we found the dependencies the reviewer points to. The

all cells of a model family shared one trained model. The revised design removes the nesting:

**R1-M3 (robustness under a hierarchical analysis).** As suggested, the inference now accounts
for the structure of the design. For each endpoint and contrast we fit a linear mixed model with
random intercepts for model and for seed within model. A cluster bootstrap over models gives
confidence intervals, and the number of models in which each difference has the same sign is
reported. The exact sign test at the model level is also given; with five models it cannot go
below p = 0.0625, and the text says so. The cell-level Wilcoxon test is kept as a description
(§3.5, Table 2). [R: whether conclusions change under the hierarchical analysis.]

**R1-M4 (fixed feature budget; different SHAP implementations).** We agree that both choices
could shape the differences. (1) LIME is now run both with its 10-feature budget and without
it (all features). The comparison of sparsity, fidelity and cost is reported for both (§3.3,
Table 2). (2) To separate the SHAP implementation from the model family, KernelSHAP is also run
on the two tree models, next to TreeSHAP (§4.3). [R: what changes with each.]

**R1-M5 (other hyperparameter configurations).** A sensitivity analysis now covers LIME's
kernel width and number of samples and KernelSHAP's number of samples and background size, on

(§4.3, Fig. 1). [R]

**R1-M6 (perturbations that preserve categorical constraints).** We agree that Gaussian noise on
one-hot columns creates observations that cannot occur. The stability analysis now compares the
original scheme with one that preserves the constraints. Noise is added to numeric features
only, and each categorical feature is resampled with a small probability from its training
distribution, so every perturbed observation is a valid row (§3.4, §4.4). [R]

**R1-M7 (LIME's low stability: protocol and kernel width).** We investigated both factors

[R: which factor explains how much.]
